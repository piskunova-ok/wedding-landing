# wedding-landing

## Название и описание

**Лендинг-приглашение на свадьбу «Анна & Михаил»** — одностраничный сайт-приглашение с формой RSVP, страницей для организаторов и backend-частью без сторонних зависимостей.

Свадьба: **24 сентября 2026, 16:00**, Усадьба «Мещерская», Гусь-Хрустальный, ул. Интернациональная, 105.

## Задача

Собрать ответы гостей: кто придёт, сколько человек, есть ли пожелания по меню — без платных конструкторов и отдельных сервисов-подписок. Готовые решения обычно не отдают данные и требуют денег, а здесь всё своё: страница, хранение, уведомления и админка.

## Для кого

- **Гости** — смотрят программу, дресс-код, локацию и подтверждают присутствие одной формой.
- **Организаторы** — открывают `/admin.html` под паролем, видят статистику и выгружают CSV.
- **Разработчики** — рабочий пример landing + API + serverless без фреймворков и сборки.

## Основные функции и сценарии

**Страница:** hero с именами и датой, липкая навигация с бургер-меню, детали и адрес с ссылкой на Яндекс.Карты, история пары, галерея с лайтбоксом (стрелки, `Esc`, клик по фону), обратный отсчёт до свадьбы, дресс-код с палитрой оттенков, программа дня из 6 пунктов, форма RSVP, «Как добраться», финальный экран, кастомная 404, анимации появления при скролле.

**Форма RSVP:** клиентская валидация с текстом ошибки → запрос в `/api/rsvp` и при её отсутствии автоматически в `/.netlify/functions/rsvp` (фоллбэк по 404 или обрыву сети) → повторная отправка блокируется → серверная валидация и rate-limit → отдельная благодарность для «придёт» и «не смогу».

**Два backend-варианта:**

| | `server.js` (локально) | `netlify/functions/rsvp.js` (прод) |
|---|---|---|
| Хранилище | `data/rsvp.json` + дубль в Supabase | только Supabase |
| Rate-limit | 10 / 10 мин на IP | 20 / 10 мин на IP |
| Уведомления | Telegram + консоль | Telegram (таймаут 8 с) |
| Зависимости | только встроенные модули | только `fetch` |

**Админка:** вход по `ADMIN_SECRET`, 4 карточки статистики (всего / придут / не смогут / число гостей), таблица ответов, кнопки «Обновить» и «Скачать CSV» (с BOM, открывается в Excel). Список приходит без IP.

**Безопасность:** `netlify.toml` закрывает `/data/*`, `/server.js`, `/package.json`, `/supabase.sql`, `/.env*` отдачей 404. В `supabase.sql` — CHECK-ограничения и RLS без политик: база доступна только по сервисному ключу. Фото кэшируются на сутки.

## Технологии

HTML5, чистый CSS3 (custom properties, Grid, Flexbox), vanilla JS (без сборки), Node.js ≥ 18 (только встроенные модули), Netlify Functions, Supabase (PostgreSQL + REST), Telegram Bot API, Google Fonts. Зависимостей в `package.json` нет — `npm install` не нужен.

## Установка, настройка и запуск

**1. Переменные окружения** — `cp .env.example .env` и заполнить:

| Переменная | Назначение |
|---|---|
| `PORT` | порт локального сервера (по умолчанию 3000) |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | хранилище для прода; ключ не попадает во фронтенд |
| `ADMIN_SECRET` | пароль `/admin.html`; если не задан — `anna-mikhail-2026`, **обязательно замените** |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления о новых ответах |
| `RSVP_NOTIFICATION_EMAIL` | только пометка в логе, письмо не отправляется |

**2. База (для прода):** создать проект Supabase → в SQL Editor выполнить `supabase.sql`. Без Supabase всё работает на `data/rsvp.json`.

**3. Локально:** `npm start` → http://localhost:3000, админка на `/admin.html`.

**4. Netlify:** импортировать репозиторий (настройки сборки берутся из `netlify.toml`), задать переменные окружения в Site settings, задеплоить.

**5. Смена контента:** дата, адрес и тексты — прямо в `index.html`; отсчёт — `CONFIG.weddingDate` в `script.js`.

## Структура проекта

```
├── index.html              # страница-приглашение
├── styles.css              # все стили
├── script.js               # меню, отсчёт, галерея, отправка RSVP
├── admin.html              # ответы гостей (CSV, статистика)
├── 404.html                # кастомная ошибка
├── server.js               # локальный backend (0 зависимостей)
├── netlify.toml            # сборка, закрытые маршруты, кэш фото
├── supabase.sql            # таблица rsvp: ограничения + RLS
├── package.json            # метаданные и скрипт запуска
├── .env.example            # шаблон окружения
├── netlify/functions/rsvp.js  # serverless backend для прода
├── img/                    # фото пары
└── data/rsvp.json          # локальные ответы (в git не попадает)
```

`data/` и `.env` намеренно исключены из репозитория — там секреты и персональные данные гостей.

## Текущие ограничения

- **Доступ к админке** — один общий пароль в query-параметре `?key=`: он попадает в историю браузера и логи хостинга, сессий и учётных записей нет. Страница открыта, закрыт только запрос данных.
- **Rate-limit в памяти процесса** — сбрасывается при перезапуске, не общий между инстансами serverless. Это защита от случайных дублей, не от атаки.
- **E-mail-уведомления не реализованы** — `RSVP_NOTIFICATION_EMAIL` только пишется в лог.
- Дубль записи в Supabase в `server.js` не `await`-ится: ошибка не влияет на ответ гостю и уходит только в лог.
- Нет редактирования, удаления и дедупликации ответов; гость не опознаётся, форма можно отправить несколько раз.
- Дата, имена и адрес **захардкожены** в `index.html` и `script.js`, единого конфига контента нет.
- Интерфейс только на русском; фото — AI-генерация (Gemini), не реальные снимки.
- Нет сжатия и WebP: страница тянет ~16 МБ картинок. Лайтбокс без свайпов и tab-trap. Тестов, линтера и CI нет.

## Планы развития

1. Сменить `ADMIN_SECRET` и убрать пароль из query-параметра.
2. Сжать фото в WebP с `<picture>` — главный выигрыш по скорости.
3. Вынести дату, адрес и тексты в `config.js`.
4. Реальная отправка e-mail через SMTP-провайдер.
5. Авторизация в админке через Supabase Auth с ролями.
6. Редактирование ответов, фильтры и поиск в админке.
7. Антибот-защита формы (honeypot или Turnstile).
8. Режим шаблона: весь контент в `config.json` для переиспользования под другую пару.
